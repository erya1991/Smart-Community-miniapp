## 4. 商户订单隔离

Mock Adapter 内部保留 `MerchantOrderContext`：`storeId / operatorId / storeName / operatorName`。所有订单列表、详情、待办、备注、备货、配送、物流发货、凭证查询及核销确认均检查当前 Store 与经营者。

兼容历史无 storeId 订单时，以原 operatorId 作为 Store 标识；新第三批订单使用实际 storeId。同一 operator 下两个不同 Store 的隔离也已验证。

跨店猜测 orderId 会返回“订单不存在或非本店订单，无权访问”；跨店凭证返回“非本店订单”，不返回该订单内容。拒绝操作不会改变订单或 timeline。

订单页折叠 Mock 面板只切换订单演示上下文，不改变第二批商品供给主体或模拟真实登录授权。真实权限控制仍需未来服务端承担。

## 6. 状态流转及保护

合法流转在 Mock Adapter 层校验，页面仅调用 Service。完成备货按方式分流；开始配送只能从商户配送“待配送”进入；确认送达只能从“配送中”进入。

未支付、支付中、支付失败、已关闭不允许履约。支付中显示“支付结果确认中”；列表不提供履约主操作。已有“售后处理中”保守阻断履约并提示原因，但不提供售后处理流程。

物流只能在“待发货”登记发货；核销只允许可核销的社区自提 / 到店订单。重复备货、送达、发货、核销明确拒绝，timeline 不重复写入。

操作日志记录动作、结果、实际操作时间；商户履约和核销记录操作人，居民确认记录联系人。商户备注使用私有 timeline 标识，住户 DTO 去除该备注及私有事件。

## 7. 普通物流字段

保留 `deliveryMethod: LOGISTICS`，增加 `logisticsCode / logisticsName / logisticsNo / shippedAt / shipmentRemark`。

物流局部面板提供公司选择、物流单号、选填发货备注。公司和单号必填，单号为 5—40 位字母、数字或短横线，备注最多 200 字。发货前有确认弹窗。

商户详情及居民详情展示物流公司、单号、发货时间。居民物流订单具有独立发货进度及确认收货按钮，不再展示商户配送状态链。

没有轨迹、查询接口、面单或运费模板。

## 8. 统一核销规则

复用 `pages/verification/index`。列表 / 详情进入只填入凭证，不自动核销；扫码只查询；手动输入核销码或订单号后查询。查询结果展示居民、商品及数量、履约方式、核销地点、当前支付与履约状态。

再次点击“确认核销”并确认弹窗后才提交。按钮存在执行中保护；编辑输入会清除旧候选，避免使用旧查询结果。

分别提示不存在、非本店、未支付、已关闭、未备货、已使用、已失效、方式或状态不可核销、阻断性售后。已使用凭证显示原结果并拒绝再次确认。

成功结果显示订单号、方式、核销时间、操作人和“已完成”。核销更新同一子订单、timeline、工作台与住户读取结果。

## 9. 工作台与页面联动

“待备货 / 待配送及发货 / 待自提及核销”数量由当前门店同一订单 Adapter 计算，返回工作台刷新。待审核商品仍复用第二批供给数据；售后仍为下一批占位。

待办分别跳转 `/pages/order/index?filter=preparing / delivery / verification`；订单列表读取参数并应用筛选。高风险作业从紧凑订单列表进入详情确认；去核销进入现有统一核销页。

详情继续 R 模式，按状态、流程、联系与快照地址、商品、金额、订单信息、私有备注、底部操作排列。当前门店的完整联系手机用于作业，列表不增加其他隐私字段。
