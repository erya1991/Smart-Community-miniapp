## 3. Store / Goods / GoodsSku 数据和状态规则

商户端新增本地供给 Adapter，沿用既有 Adapter / Service 组织方式。页面通过 Service 获取及变更数据，商品种子从已有商户商品 Mock 转换，再补足本批状态。

| 业务对象 | 本批字段与规则 |
| --- | --- |
| Store / 入驻 | `APPLY / APPLYING / REFUSED / OPEN / CLOSED`；申请草稿及审核锁定；审核通过不自动建立合作、支付或分账关系。 |
| Goods | `storeId / goodsName / categoryId / goodsImage / goodsGallery / unit / sellingPoint / detail / deliveryMethods / skuList`；本地 `draft` 与平台审核状态分开；`auditStatus = TOBEAUDITED / PASS / REFUSE`；`marketEnable = UPPER / DOWN`；`authMessage` 为驳回原因；平台强制下架标记不能由商户 payload 清除。 |
| GoodsSku | `specs / sn / price / cost / quantity / weight / skuImage / isMain`；页面价格以元输入，Adapter 内金额使用整数分，重量单位 kg；一个主规格；同一商品规格结构一致；规格组合及编码不可重复，编码也不可与其他本店商品冲突。 |
| 经营基础资格 | 商户审核通过、店铺启用、必要资质有效、合作协议有效；满足后可维护商品并提交审核。 |
| 正式交易资格 | 在基础资格上增加支付接入与本场景所需的分账条件；满足后仍须商品审核通过、有库存、未被平台强制下架才能上架。 |

关键商品资料或 SKU 编码 / 规格 / 价格 / 成本 / 重量 / 主规格等发生改变，保存后下架并回到本地草稿，须重新审核。仅调整库存保留已通过结果。提交后商品保持下架，不能直接上架；驳回原因保存后保留，重新提交后清除旧审核原因。页面与 Adapter 均有提交中保护，重复创建 / 重复审核提交受到阻止。

初始八个商品覆盖：单规格销售中、多规格销售中、待审核、已驳回、已通过下架、库存为零、草稿，以及平台强制下架。所有初始 SKU 均包含编码、销售价、成本、库存、重量。默认资格为“基础资格有效，支付 / 分账待完善”。
