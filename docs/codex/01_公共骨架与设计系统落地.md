# 01｜Codex 阶段任务：公共骨架与 Design System 落地

## 1. 阶段目标

本阶段只建立稳定的前端基础，不深挖完整业务闭环。

完成：

- 工程扫描和复用分析；
- Design System V1.1 工程化；
- 公共组件基础；
- 住户端四 Tab 和一级页面框架；
- 商户端四 Tab 和一级页面框架；
- Project 上下文；
- 统一页面状态；
- Mock Adapter 基础。

不要在本阶段提前完成 01/02 的全部业务详情。

## 2. 必读资料

先读取：

- `AGENTS.md`
- `docs/implementation/V1.0_小程序页面实施清单.md`
- `docs/design/MiniApp_Design_System_V1.1.md`
- `docs/design/Stitch视觉母版映射表.md`

PRD 只按当前一级页面实际需要读取相关概述和总体规则，不需要一次全文载入。

Stitch 只读取：住户首页、住户服务页、住户商城首页、住户个人中心、商户工作台、商户商品管理/经营页对应母版。

## 3. 先完成工程扫描

改代码前先输出：

1. 当前目录结构；
2. yudao-mall-uniapp 已存在页面/组件；
3. 登录、请求、Store、商品、订单、支付能力；
4. 当前主题样式体系；
5. 当前 Tab/路由组织方式；
6. 可直接复用能力；
7. 与新 Design System 的冲突；
8. 预计新增/修改文件。

得到扫描结论后再执行代码修改。

## 4. Design System 工程化

把 V1.1 中品牌色、状态色、文本色、页面/卡片背景、圆角、间距、页面 gutter、按钮高度、最小触控尺寸、Tab 高度落到统一 theme / `uni.scss` / 公共样式层。

禁止页面自行再定义主色体系。

## 6. 住户端 App Shell

固定：`首页｜服务｜商城｜我的`

### 首页

按 Stitch 母版实现：当前社区/项目、消息入口、单主视觉、8 个快捷入口、便民服务、社区好物。

商城入口可接真实商城。P2-P5 未开发能力使用统一 `FeatureUnavailable` / “建设中”状态。

### 服务

建立五类导航：生活缴费、我的社区、社区服务、邻里生活、购物消费。

商城入口可用。其他未完成专题只做入口和占位。

### 商城

优先复用现有商城首页和商品能力，完成新视觉统一，不重造商城内核。

### 我的

完成个人中心分组框架：我的订单、我的服务、我的社区、邻里生活、积分、地址、消息、反馈、设置。

已完成能力接真实页面，未开发能力占位。

## 7. 商户端 App Shell

固定：`工作台｜经营｜订单｜我的`

确保与居民端 Tab 配置隔离，不能串端。

### 工作台

先完成视觉骨架：当前商户/门店/经营状态、待办、快捷操作、今日经营、资金摘要。允许 Mock Adapter。

### 经营

建立：商品、服务（后续开放）。商品可接当前现有能力或 Mock。

### 订单

建立商城订单列表容器和入口，不在本阶段完成全部履约。

### 我的

建立入口：基本资料、门店、人员、资质、合作状态、经营资格、消息、设置。

## 8. Project 上下文

建立明确 `currentProject`。

要求：住户首页/商城读取当前项目；商户端后续可以承载当前 Project + Operator + Store；一期默认大光路可以作为初始化值；业务逻辑不能永久写死单项目；后端权限仍为最终依据。

## 9. Mock Adapter

允许本阶段使用 Mock。

要求：Mock 通过统一 Adapter / Service 层；页面不直接硬编码业务对象；字段尽量来自 PRD；后续真实接口可替换；不编造渠道、银行、分账时效等规则。

## 10. 页面状态

所有本阶段正式页面至少支持：loading、empty、error、unavailable。

## 11. 验收

阶段完成标准：

- 两端四 Tab 稳定；
- 不串端；
- Design Token 已统一；
- 公共组件开始沉淀；
- 住户四个一级页面完成；
- 商户四个一级页面骨架完成；
- Project 上下文可用；
- 未开发业务统一占位；
- 没有第二套视觉体系；
- 当前工程可以支撑阶段 02 开发。

完成后按 `AGENTS.md` 的阶段汇报格式输出，并停止。
