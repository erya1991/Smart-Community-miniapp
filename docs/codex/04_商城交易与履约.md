# 04｜Codex 阶段任务：商城交易与履约

## 1. 阶段目标

实现《02｜社区商城完整闭环》中从“确认订单 → 支付结果 → 商户订单 → 三类履约 → 居民订单详情”的前端闭环。

售后与评价留到阶段 05。

## 2. 必读资料

必须读取：AGENTS.md、02 PRD、01 PRD 中正式交易资格、页面实施清单、Design System V1.1、Stitch 映射表。
- `docs/design/MiniApp_WeChat_Implementation_Guidelines_V1.0.md`
- `docs/codex/00_Stitch视觉还原协议.md`

重点读取 02：2.5、2.6.2、2.6.3、4.9、4.10、4.11、4.12、4.13、4.15、4.16、4.17、5.4、5.5、5.6。

Stitch 按需：确认订单、居民订单详情、商户订单详情、商户工作台、核销页面。

## 3. 阶段前扫描

确认商品/SKU、购物车、商品详情、Project/Operator、订单状态组件、AmountSummary、StatusTimeline、ResultState、API/Mock Adapter。先给出实施计划。

## 4. 收货地址

实现地址列表、新增、编辑、删除、默认地址。商户配送必须选择地址。自提/到店核销不要求配送地址，但要保留联系人/手机号。历史订单使用快照。

## 5. 确认订单与创建订单

一次只结算一个商户。

实现商品、商户、履约方式、地址/自提点/门店、联系人、金额、买家留言、售后说明、提交订单。

只显示当前商品实际支持的履约方式。

提交前处理价格变化、库存变化、商品下架、履约条件变化、资格不足、重复提交。

## 6. Pay 抽象

只接统一 Pay。

前端稳定状态：未支付、支付中、支付成功、支付失败、已关闭、Mock 成功。

禁止写死微信渠道内部字段。

支付结果未知保持处理中并主动查询。

## 7. 商户工作台真实化

升级为真实商城待办：待审核商品、待备货、待配送、待自提/核销、售后待处理占位、今日支付订单/金额、待分账/已分账摘要。

不得展示银行/到账承诺。

## 8. 商户订单

实现列表、详情、状态筛选、履约操作、商户备注、资金统一状态摘要。负责人和门店人员数据范围不同。

## 9. 三类履约

商户配送：待备货 → 待配送 → 配送中 → 已送达 → 已完成。

社区自提：待备货 → 待自提 → 已核销 → 已完成。

到店核销：待核销 → 已核销 → 已完成。

不做骑手系统。

## 10. 核销

实现扫码、手工输入、查询订单、核对订单、确认核销、成功和异常。

扫码后不得直接自动核销。

异常至少覆盖：不存在、已核销、已失效、状态不可核销、无权限、非当前门店。

## 11. 居民订单

实现全部、待支付、待履约、待收货/待核销、已完成、售后/退款入口占位。

订单详情只展示当前实际履约方式。

## 12. 多状态原则

独立处理交易状态、支付状态、履约状态、售后状态、退款状态、分账状态。页面可选主展示状态，但代码模型不得用单一状态覆盖全部维度。

## 13. 本阶段禁止事项

不要实现微信分账 API、售后详细处理、评价、骑手调度、银行到账推导；前端不得决定最终库存/资格；不要把自动确认时长写死成不可配置常量。

## 14. 验收

完成条件：一订单一商户；地址/履约正确；Pay 抽象正确；Mock Pay 可跑通；两端订单可用；三类履约正确；核销流程防重复；工作台待办可穿透；多状态模型不被错误合并。

完成后按 `AGENTS.md` 汇报并停止。
