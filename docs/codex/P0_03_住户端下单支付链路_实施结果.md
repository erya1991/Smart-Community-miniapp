## 3. CheckoutContext 数据模型

顶层为 merchantGroups[]、默认地址 / 联系人和整体金额；items 为报价校验用的扁平快照。已移除旧顶层单商户身份和单个 defaultFulfillment / fulfillmentMethods。

每组包含 storeId / operatorId、商户 / 店铺名称与地址、商品快照、实际可用履约方式、默认方式、pickupPoints[]、verificationStore、配送说明和商品金额 / 运费 / 优惠 / 小计。页面以 choices[] 保存逐店履约方式、点位 ID 和最大 100 字买家备注。

优先使用实际 storeId；旧 Mock 尚无独立 storeId 时用 operatorId 作明确兼容键。同一经营者两个不同 Store 的独立履约已通过隔离场景验证。

## 4. Trade 与商户子订单

TradeSummary 包含 tradeId / tradeSn / memberId、商品金额、运费、优惠、应付 / 已付、支付状态、创建时间、30 分钟 expiresAt 和 orders[]。每个子订单记录 tradeId / storeId / operatorId、商品 / SKU / 数量 / 单价及履约、地址、联系人、备注和金额快照。

同一次结算创建一笔 Trade 和各商户子订单，一个 payOrderId 对应整笔交易。支付结果同步所有子订单。新页面按 tradeId 调用支付；既有详情 orderId 支付链接通过 getTradeForOrder 解析兼容。多商户结果进入已有订单列表，单商户进入已有详情。

旧 projectId 字段仅保留历史订单与共享类型兼容；本轮没有添加 Project 页面、选择或授权业务。

## 5. 多商户分组与结算

购物车继续按店铺展示，不再提供逐组独立结算按钮。仅底部全选、已选件数、金额、结算按钮提交全部选中有效 cartIds。不存在的条目不得静默漏单。

商品未审核上架、SKU 失效、库存不足、店铺停用 / 经营或交易资格不可用均排除选择与金额，展示原因并支持移除 / 一键清空。数量必须为安全正整数且不超库存，页面按钮边界与 Adapter 双重校验。

创建成功只移除本次实际结算条目；其他条目保留。

## 6. 四种履约方式

| 用户文案 | 后续映射 | 收货信息 |
| --- | --- | --- |
| 商户配送 | LOCAL_TOWN_DELIVERY | 必须完整地址快照；展示商户配送说明 |
| 社区自提 | SELF_PICK_UP | 点位名称 / 地址 / 电话 / 营业时间及取货说明；无需配送地址 |
| 到店核销 | SELF_PICK_UP + 门店点位 | 门店信息及核销说明；支付成功后生成凭证 |
| 普通物流 | LOGISTICS | 必须完整地址快照；说明后续商户更新物流信息 |

只有某组选择配送或物流时，确认页才显示顶层地址。各组选择独立；支持后续多个 pickupPoints，无 PC 表格或全局单履约变量。

本轮不接物流或运费服务。Mock 各组运费、优惠均为 0 分，页面明确展示报价；不代表生产运费策略。

## 7. 地址选择与默认地址

地址页 select=1 & checkoutKey 接收本次结算会话标识。点击地址只写临时选择、返回确认页，不调用 setDefaultAddress。显式“设为默认”或编辑表单默认选项才改变默认标记。

保持新增 / 编辑 / 删除；第一条地址自动默认，删除默认地址后选另一条。错误可持续查看。历史订单保存独立地址快照，编辑 / 删除不会改变快照；不增加房屋、楼栋绑定关系。

## 8. 提交校验与原子性

提交重新校验审核 / 销售状态、店铺启用与经营 / 交易资格、SKU 有效性、合计库存、最新价格与预期金额、逐组履约、点位、完整地址、联系人及 11 位手机号、备注长度、模拟正式交易资格与 Mock Pay 可用性。

错误返回具体原因；确认页可刷新报价后再次确认。一次结算会话复用幂等 key，页面 loading 防重复点击，成功后不再创建交易。校验全部完成后同步预占全部 SKU；任一预占或最终购物车步骤失败回滚已预占库存，不记录半笔交易或子订单。Mock 内部购物车删除为原子数组替换，此逻辑不声称具备生产分布式事务能力。

## 9. 支付状态机

未支付 → 支付中 / 支付成功 / 支付失败；失败保留待支付订单及预占库存，原 Trade 可重试。支付中不得重复发起支付，页面只在 Adapter 查询确认后显示成功。查询的演示确定结果为成功。

取消或超时关闭整笔交易、同步全部子订单并只释放一次库存；已支付交易不可取消，重复支付 / 回调不重复更新。到店与自提凭证仅在成功后生成。超时在交易 / 订单读取或支付操作时检查，不依赖真实定时服务。

支付结果展示金额、交易号、子订单数、查看订单和返回商城。主流程使用产品文案，Mock 控制只在默认折叠的“原型演示 / Mock”区；没有居民佣金或分账展示。
