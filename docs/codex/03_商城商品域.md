# 03｜Codex 阶段任务：商城商品域

## 1. 阶段目标

实现《02｜社区商城完整闭环》中“商品发现 + 商品经营 + SKU/库存 + 购物车”的小程序前端。

本阶段不进入正式订单支付、履约、售后。

## 2. 必读资料

必须读取：

- `AGENTS.md`
- `docs/requirements/02_社区商城完整闭环_V1.0.md`
- `docs/requirements/01_平台基础模型与商户合作关系_V1.2.md` 中资格相关规则
- 页面实施清单
- Design System V1.1
- Stitch 映射表
- `docs/design/MiniApp_WeChat_Implementation_Guidelines_V1.0.md`
- `docs/codex/00_Stitch视觉还原协议.md`

重点 02：2.5、2.6 商品状态、4.2、4.3、4.5、4.6、4.7、4.8、5.1/5.2/5.6 相关规则。

Stitch 按需：商城首页、商品详情、商品管理、商品新增/编辑、购物车。

## 3. 阶段前扫描

确认 Project / Operator 上下文、经营资格访问能力、公共表单、ProductCard、StatusTag、Service/API 层、Mock Adapter。先输出“直接复用 / 改造 / 新增”的实施计划。

## 4. 商户端商品经营

### 商品管理

实现列表、搜索、状态筛选、商品卡片和当前允许操作。

审核状态：草稿、待审核、已驳回、已通过。

销售状态：未上架、销售中、已下架。

不得合并。

### 新增/编辑商品

按 PRD 实现项目、商户、门店、类目、名称/卖点、主图/轮播、详情、履约方式、配送说明、售后说明、SKU/库存、预览提交。

操作：保存草稿、提交平台审核。

### SKU 与库存

实现单/多规格、SKU 图片、销售价、划线价、SKU 编码、可售库存、占用库存只读、预警值、库存调整。

不要做 PC 表格体验。

### 审核结果与上下架

实现待审核撤回、驳回原因、修改重提、审核通过后上架、销售中下架、已下架重新上架。

## 5. 住户端商品发现

### 商城首页/分类/列表

实现当前 Project、分类、搜索、商品列表、商户、履约标签、售罄/库存紧张。

### 商品详情与 SKU

实现当前线上审核版本、SKU 联动、商户/门店公开信息、履约方式、售后说明、加入购物车、立即购买入口。

立即购买本阶段只进入确认订单路由占位。

### 购物车

实现多商户分组、SKU 数量、失效商品、最新价格/库存、同 SKU 合并、每个商户独立结算。

核心：购物车可以多商户，一次结算只能一个商户。

## 6. 商品资格依赖

商品草稿可只校验主体身份。提交审核、上架必须校验业务经营资格。正式下单需要正式交易资格，但属于下一阶段。

## 7. 库存原则

前端库存只用于体验，不实现最终超卖判断。正确展示可售库存、占用库存、库存不足、SKU 失效、商品下架。

## 8. 本阶段禁止事项

不要实现正式订单创建、Pay、配送/核销、售后、跨商户合单、团购/秒杀/复杂优惠、骑手；不要建立第二套 Mall Product/SKU 内核。

## 9. 验收

完成条件：商户商品经营闭环；双状态正确；SKU/库存可用；住户商城发现完整；商品详情按线上版本；购物车按商户分组；无跨商户结算；复用 Mall，不重造内核。

完成后按 `AGENTS.md` 汇报并停止。


## 视觉实现要求

本阶段所有页面必须遵守：

禁止只完成信息结构而宣称视觉完成。
