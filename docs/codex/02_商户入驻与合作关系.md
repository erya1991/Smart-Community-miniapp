# 02｜Codex 阶段任务：商户入驻与合作关系

本阶段完整实现商户小程序中《01｜平台基础模型、商户入驻与合作关系》相关前端页面。

只实现商户小程序，不实现对应 Web 管理后台。

覆盖：入驻申请、审核结果、基本资料、门店、商户人员、资质、合作状态、经营资格。

## 3. 先扫描现有阶段 01 产物

确认商户端路由和 Tab、公共表单、Project / Operator 上下文、Mock Adapter / API Service、已有占位入口。先给出实施计划，再修改。

## 4. 页面范围

### 4.1 入驻申请

实现：草稿保存、分步骤填写、驳回后修改重提、待审核/已通过只读、项目上下文只读。

必须区分 OperatorApplication 与正式 Operator。

状态：草稿、待审核、已通过、已驳回。

操作：保存草稿、上一步/下一步、提交审核。

### 4.2 审核结果

显示当前状态、最近提交时间、审核时间/意见、驳回原因、历史记录。驳回后回申请修改；通过后进入正式资料。

### 4.3 基本资料

区分可维护非核心字段与只读核心主体字段。核心字段变更不在小程序直接完成。

### 4.4 门店

实现列表、新增、编辑、停用、恢复。门店不是独立资格主体。

### 4.5 商户人员

实现列表、邀请、角色、门店范围、停用、负责人转交。最后一名有效负责人不能直接停用。

### 4.6 资质

实现列表、状态、新增/更新、有效期、附件、原因。未经平台确认不能显示为已生效资格。

### 4.7 合作状态

只读展示当前项目、合作协议、项目合作、经营授权。商户端不得编辑协议、合作、授权。

### 4.8 经营资格

必须分区：业务经营资格、资金接入状态、正式交易资格。

业务资格有效而资金配置中时：允许维护经营内容，暂不可正式收款。

不得把资金异常显示成主体审核失败。

## 5. Stitch 母版

入驻申请用分步骤表单母版；经营资格/合作状态用资格解释母版；资料/门店/资质编辑用复杂表单母版；管理列表用商户管理列表母版。母版编号以映射表为准。

## 6. 接口策略

优先复用现有 API。后端接口尚未存在时，建立清晰 API Service + Mock Adapter；Mock 字段必须来自 PRD；汇报时明确真实/Mock 边界。

不要自行设计与 PRD 冲突的接口字段。

## 7. 权限与状态

至少考虑商户负责人、普通工作人员。负责人和普通人员操作范围必须区分。前端只控制展示，最终权限以后端为准。

## 8. 本阶段禁止事项

不要开发 Web 后台；不要进入商城商品业务；不要实现微信支付/分账；不要用单一“商户状态”合并主体、合作、授权、资金；不要让门店独立获得主体资格；不要自行实现街道/网格审核；不要自动开通正式交易资格。

## 9. 验收

完成条件：商户入驻主链完整；申请与正式主体分离；门店/人员/资质完整；合作状态只读；两层资格正确；Project/Operator 数据范围明确；真实接口/Mock 边界清楚。

完成后按 `AGENTS.md` 汇报并停止。
