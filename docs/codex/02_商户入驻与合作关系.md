# 02｜Codex 阶段任务：商户入驻与合作关系

## 1. 阶段目标

本阶段完整实现商户小程序中《01｜平台基础模型、商户入驻与合作关系》相关前端页面。

只实现商户小程序，不实现对应 Web 管理后台。

覆盖：

- 入驻申请；
- 审核结果；
- 基本资料；
- 门店；
- 商户人员；
- 资质；
- 合作状态；
- 经营资格。

本阶段目标是：

> **业务链完整、页面可用、状态正确、视觉与现有商户端保持一致。**

阶段 01.6 的一级页面视觉骨架已经冻结。本阶段不进行跨页面的最终 UI / UX 精细打磨；最终细节优化统一在主要业务功能完成后，基于完整业务流、真实数据长度和真机状态进行。

## 4. 页面范围

### 4.1 入驻申请

实现：

- 草稿保存；
- 分步骤填写；
- 驳回后修改重提；
- 待审核只读；
- 已通过只读；
- 项目上下文只读。

必须区分：

```text
OperatorApplication
≠
正式 Operator
```

状态：草稿、待审核、已通过、已驳回。

操作：保存草稿、上一步、下一步、提交审核。

页面性质：

> Merchant Process / R 模式。

### 4.2 审核结果

显示：当前状态、最近提交时间、审核时间、审核意见、驳回原因、历史记录。

规则：

- 驳回后返回申请修改；
- 通过后进入正式资料。

页面性质：

> Merchant Process / R 模式。

### 4.3 基本资料

区分：

- 可维护非核心字段；
- 只读核心主体字段。

核心主体字段变更不在小程序直接完成。

页面性质：

> Merchant Process / R 模式。

### 4.4 门店

门店不是独立资格主体。

#### 4.4.1 门店列表

实现：门店列表、当前状态、主要门店信息、新增入口、编辑入口、停用、恢复。

页面性质：

> Merchant Operational / O 模式。

要求：

- 一个列表项代表一个门店；
- 状态直接可见；
- 高频操作直接可见；
- 不使用大面积展示型卡片；
- 不为了紧凑删除必要字段。

#### 4.4.2 门店新增 / 编辑

实现新增和编辑所需字段、校验、保存和异常反馈。

页面性质：

> Merchant Process / R 模式。

### 4.5 商户人员

#### 4.5.1 商户人员列表

实现：人员列表、当前角色、门店范围、当前状态、邀请入口、编辑入口、停用、负责人转交入口。

规则：

> 最后一名有效负责人不能直接停用。

页面性质：

> Merchant Operational / O 模式。

#### 4.5.2 人员邀请 / 编辑

实现：邀请、角色、门店范围、编辑、负责人相关操作。

页面性质：

> Merchant Process / R 模式。

### 4.6 资质

#### 4.6.1 资质列表

实现：资质名称、当前状态、有效期、是否临期/过期、最近审核状态、更新入口、查看原因入口。

未经平台确认不能显示为已生效资格。

页面性质：

> Merchant Operational / O 模式。

#### 4.6.2 资质新增 / 更新

实现：资质填写、有效期、附件、提交、驳回后重新提交、原因展示、上传反馈。

页面性质：

> Merchant Process / R 模式。

### 4.7 合作状态

只读展示：

- 当前项目；
- 合作协议；
- 项目合作；
- 经营授权。

商户端不得编辑协议、合作关系、项目授权。

页面性质：

> Merchant Process / R 模式。

### 4.8 经营资格

必须分区展示：

1. 业务经营资格；
2. 资金接入状态；
3. 正式交易资格。

规则：

- 业务资格有效、资金配置中：允许维护经营内容；
- 资金未就绪：暂不可正式收款；
- 资金异常不得显示成主体审核失败；
- 业务经营资格与正式交易资格不得合并。

页面性质：

> Merchant Process / R 模式。

## 5. Stitch 母版与页面视觉模式

本阶段页面必须同时从 `docs/design/Stitch视觉母版映射表.md` 读取：

- Stitch Level：L1 / L2 / L3；
- Visual Mode：R / O。

### 5.1 Merchant Process｜流程型

包括：

- 入驻申请；
- 审核结果；
- 基本资料；
- 门店新增 / 编辑；
- 人员邀请 / 编辑；
- 资质新增 / 更新；
- 合作状态；
- 经营资格。

默认使用：

> R｜Replica Mode。

目标：

> 流程清楚、字段完整、状态解释明确、错误可恢复。

不得为了提高信息密度压缩：

- 表单字段；
- 分步流程；
- 状态说明；
- 风险提示；
- Bottom Action；
- 错误反馈。

### 5.2 Merchant Operational｜作业管理型

包括：

- 门店列表；
- 商户人员列表；
- 资质列表。

默认使用：

> O｜Operational Mode。

目标：

> 在有限移动屏幕中快速查看状态、定位对象并执行管理操作。

要求：

- 减少大卡片和无意义留白；
- 一个列表项代表一个主要业务对象；
- 必要字段完整；
- 状态和主操作直接可见；
- 紧凑视觉控件保持至少 44px 实际点击热区；
- 不因为“参考 Stitch”重新做成展示型大卡片。

本阶段不得因为“都是商户端页面”统一采用一种信息密度。

## 7. 接口策略

优先复用现有 API。

后端接口尚未存在时：

- 建立清晰 API Service；
- 建立 Mock Adapter；
- 页面不直接散落 Mock；
- Mock 字段必须来自 PRD；
- 汇报时明确真实接口 / Mock 边界。

不要自行设计与 PRD 冲突的接口字段。

一期允许 Mock 支撑前端完整业务流，但 Mock 不得演变为另一套业务模型。

阶段 02 必须继续遵守：

```text
currentProject
```

- OperatorApplication 不是正式 Operator；
- Store 不是独立主体资格；
- 前端上下文不能扩大后端权限；
- 不通过角色切换另一个 App Shell。

## 9. 权限与状态

至少考虑：

- 商户负责人；
- 普通工作人员。

必须区分：

- 可查看；
- 可新增；
- 可编辑；
- 可停用；
- 可转交负责人；
- 只读状态。

前端只控制展示和交互可用性，最终权限以后端权限控制为准。

---

## 10. 本阶段禁止事项

不要：

- 开发 Web 后台；
- 进入商城商品业务阶段；
- 实现微信支付 / 分账；
- 用单一“商户状态”合并主体、合作、授权、资金；
- 让门店独立获得主体资格；
- 自行实现街道 / 网格审核；
- 自动开通正式交易资格；
- 将资金异常显示成主体审核失败；
- 因为是商户端就全部使用 Operational 高密度布局；
- 为了追求 Stitch 相似度牺牲管理列表作业效率；
- 修改阶段 01.6 已冻结一级页面的整体视觉结构。

## 11. 视觉实现要求

本阶段所有页面必须遵守：

- `docs/codex/00_Stitch视觉还原协议.md`
- `docs/design/Stitch视觉母版映射表.md`
- `docs/design/MiniApp_Design_System_V1.1.md`
- `docs/design/MiniApp_WeChat_Implementation_Guidelines_V1.0.md`

开发每个页面前：

1. 查询页面实施清单；
2. 读取 PRD 对应章节；
3. 查询当前页面 Stitch Level；
4. 查询当前页面 Visual Mode；
5. L1 / L2 打开必要 `screen.png`；
6. 必要时读取 `code.html`；
7. 再进行实现。

### 11.1 R 模式验收

运行页面截图与 Stitch 母版进行直接视觉对照。

重点检查：

- 构图；
- 模块顺序；
- 卡片关系；
- Typography；
- 间距；
- 状态表达；
- 表单和 Bottom Action；
- 微信胶囊和 safe-area。

不要求在当前阶段追求最终像素级精修，但页面不得明显偏离已确认母版和 Design System。

### 11.2 O 模式验收

Stitch 不是像素级几何验收标准。

重点检查：

- 页面必要业务字段是否完整；
- 高频状态是否容易识别；
- 主操作是否直接可见；
- 是否存在无意义大卡片和空白；
- 一屏有效业务信息是否合理；
- 是否一个列表项对应一个主要业务对象；
- 紧凑视觉按钮与 Chip 是否保持 ≥44px 有效点击热区；
- 是否仍保持 Design System 的颜色、字体、图标和卡片语言。

禁止为了追求 Stitch 相似度，降低 Merchant Operational 页面的作业效率。

## 12. 页面状态与异常

所有正式页面至少考虑：

- loading；
- empty；
- error；
- network error；
- no permission；
- disabled；
- business unavailable。

提交型页面增加：

- submitting；
- duplicate submit；
- validation error。

表单错误必须字段原位提示，并给出如何修改，不只显示短暂 Toast。

- 商户入驻主链完整；

```text

boundary check
```

具体命令以当前 `package.json` 为准。
