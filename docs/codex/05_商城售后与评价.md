# 05｜Codex 阶段任务：商城售后与评价

## 1. 阶段目标

完成《02｜社区商城完整闭环》的小程序端最后一段：取消订单、居民售后、商户售后、平台处理状态、退款结果、商品评价、商户评价查看与回复。

完成后，当前 02 社区商城小程序端形成完整 P1 闭环。

## 2. 必读资料

必须读取：AGENTS.md、02 PRD、页面实施清单、Design System V1.1、Stitch 映射表。
- `docs/design/MiniApp_WeChat_Implementation_Guidelines_V1.0.md`
- `docs/codex/00_Stitch视觉还原协议.md`

重点读取 02：2.6.4、4.18、4.19、4.20、4.21、4.22、4.24、5.1、5.4、5.6、5.7、5.8。

Stitch 按需：居民售后申请、居民售后详情、商户售后详情与处理、居民订单详情。

## 3. 阶段前扫描

确认已有订单/履约/支付状态、AmountSummary、StatusTimeline、EvidenceUploader、API/Mock Adapter、Pay 稳定状态。先输出实施计划。

## 4. 未支付取消

待支付订单可由居民取消，不创建退款单。成功后刷新订单状态；库存释放属于后端结果。

## 5. 居民售后申请

实现订单/订单项、售后类型、退款数量、申请金额、原因、说明、凭证。

规则：说明最多 500 字；图片最多 9 张；售后类型按履约阶段；累计退款不超剩余可退；商户处理前允许撤销；提交防重复。

页面不得写死 24 小时必处理、超时自动退款、街道/网格员介入。

## 6. 商户售后处理

实现售后列表、详情、同意仅退款、同意退货退款、确认收到退货、拒绝、提交平台处理。

规则：拒绝原因必填；商户不能提高申请金额；超时只提醒，一期默认不自动同意；已分账进入资金回退处理中；不在页面执行渠道分账回退。

高风险操作二次确认。

## 7. 居民售后详情/退款结果

显示：商户处理中、平台处理中、已同意、已拒绝、资金回退处理中、退款中、退款成功、退款失败、已撤销。

只使用“原支付路径退款”，不得写死微信账户、银行到账、T+1。

退款失败时不要让居民重复提交售后。

## 8. 平台处理边界

小程序只展示已申请平台处理、平台处理中、平台处理结果。不开发 Web 仲裁后台。不创造街道调解、网格员协调、社区驿站仲裁。

## 9. 商品评价

居民端实现订单项、1–5 星、评价内容、图片、匿名。

规则：内容最多 500 字；图片最多 9 张；一订单项一条有效首评；已完成订单才可评价；匿名只隐藏公开昵称，不改变后台关联。

## 10. 商户评价

实现评价列表、门店/商品/星级/时间筛选、评价详情、一次公开回复。

规则：回复最多 300 字；一条评价仅一次回复；商户不能修改评分；不能自行隐藏评价；匿名居民不可被商户反查真实身份。

## 11. 售后/资金多状态

代码中继续保持售后状态、退款状态、分账状态独立。售后同意不等于退款成功。已分账不等于不能退款，而是需要进入资金回退流程。

## 12. 消息与刷新

状态变化后居民订单详情、商户订单详情、工作台售后待办、售后列表、退款结果应正确刷新或重新拉取。消息发送失败不回滚核心业务状态。

## 13. 本阶段禁止事项

不要实现 Web 售后监管；不要实现微信渠道退款 API 细节；不要自动超时同意；不要新增换货/维修/补发；不要新增复杂退货物流；不要建新的评价体系；不要将售后状态覆盖订单主状态。

## 14. 验收

完成条件：未支付取消正确；居民售后字段/限制正确；商户处理正确；平台处理状态可展示；退款状态清楚；资金回退状态正确；居民评价可用；商户回复可用；三类状态不混淆；Stitch Mock 不覆盖 PRD。

完成后按 `AGENTS.md` 汇报。

本阶段完成即代表当前 02 社区商城小程序 P1 前端主闭环完成。不要自行开始 P2 社区服务，等待新的 03 PRD。
