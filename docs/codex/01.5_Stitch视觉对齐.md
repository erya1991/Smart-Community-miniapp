# 01.5｜Codex 阶段任务：Stitch 视觉对齐

> 阶段定位：阶段 01 完成后的视觉校准阶段  
> 适用对象：住户端一级页面 + 商户端一级页面  
> 目标：**保留阶段 01 已完成的工程基础，只校准页面结构、公共组件视觉和图标体系，使最终页面与 Stitch 最终母版达到明显一致。**  
> 本阶段不是业务功能扩展阶段，不进入 01 商户合作关系或 02 商城业务深度开发。

---

# 1. 为什么需要本阶段

阶段 01 已完成：

- 两端 App Shell；
- Design Token；
- 公共组件；
- Project 上下文；
- Mock Adapter；
- 一级页面基本结构。

但当前部分页面存在明显问题：

- 只还原了信息结构，没有还原 Stitch 页面构图；
- 页面标题区被重新设计；
- Quick Entry 被做成了新的卡片结构；
- 图标使用汉字占位；
- Bottom Tab 与 Stitch 差异较大；
- 组件化过程改变了最终视觉；
- “遵循 Design System”被误解成“可以重新设计页面”。

因此本阶段要正式建立：

> **有 Stitch 母版的页面，screen.png 是视觉验收基准。**

Design System 负责统一 Token 和组件规则；  
Stitch `screen.png` 负责具体页面布局和视觉层级；  
Stitch `code.html` 只帮助理解间距、尺寸和结构，不直接复制 Web 代码。

# 4. 核心视觉优先级

凡存在 Stitch 母版的页面，视觉还原必须按以下优先级执行：

1. 页面模块顺序与 Stitch 一致；
2. 页面主要几何结构与 Stitch 一致；
3. 顶部导航 / 页面标题区结构与 Stitch 一致；
4. 卡片尺寸、列数、留白、对齐方式接近 Stitch；
5. Quick Entry 的图标、文字关系与 Stitch 一致；
6. Bottom Tab 的结构、层级和激活态与 Stitch 一致；
7. 字号、颜色、圆角、边框服从 Design System V1.1；
8. 可以组件化，但组件化不得改变最终视觉结构；
9. uni-app / 微信安全区适配优先于像素级复制；
10. 最终目标不是“功能差不多”，而是：

> **肉眼第一眼看上去就是同一套设计。**

# 6. 图标处理规范

当前阶段必须清理：

```text
缴
停
房
服
全
```

这类汉字占位图标。

正式图标策略按以下顺序：

1. 优先使用当前项目已经存在的图标库；
2. 如果已有 iconfont / uni-icons / 项目 SVG 资源，优先复用；
3. 若没有对应图标，可新增本地 SVG；
4. 图标视觉需保持简洁线性、统一线宽；
5. 图标必须与功能名称同时出现；
6. 不引入 Material Symbols Web 字体；
7. 不因为缺少图标就继续使用汉字占位；
8. 不使用 emoji 作为正式图标。

优先覆盖：

- 物业缴费；
- 停车缴费；
- 房屋绑定；
- 我的房屋；
- 车辆管理；

- 更多服务；

### B.2 搜索框

# 8. Design System 与 Stitch 的边界

如果 Stitch 与 Design System 出现轻微视觉差异：

## 8.1 以下由 Design System 决定

- 主品牌色；
- 字号体系；
- 状态色；
- 圆角 Token；
- 按钮高度；
- 最小触控区；
- Bottom Tab 名称；
- 两端视觉统一原则。

## 8.2 以下由 Stitch 决定

- 页面模块顺序；
- 具体分区方式；
- 卡片组合方式；
- 一行几个功能入口；
- 标题区布局；
- 图片与文本的相对关系；
- 页面大体留白和信息密度。

禁止因为公共组件方便而修改 Stitch 的页面构图。

# 10. 视觉校准方法

每张页面完成后，都执行一次以下对照：

```text
Stitch screen.png
vs
当前运行页面
```

至少逐项检查：

### 结构

- 顶部结构是否相同？
- 模块顺序是否相同？
- 是否增加/减少了不该出现的容器？

### 几何

- 页面左右边距是否接近？
- 卡片宽度是否接近？
- 卡片间距是否接近？
- 一行入口数量是否一致？
- 是否产生大量无意义空白？

### Typography

- 标题层级是否接近？
- 是否出现过大/过粗字体？
- 功能名称是否频繁换行？

### Icon

- 是否均为真实图标？
- 图标底是否一致？
- 是否仍存在汉字占位？

### Bottom Tab

- 是否与 Stitch 属于同一种样式？
- 是否出现独立边框卡片？
- 激活态是否正确？

### 色彩

- 是否统一黛青主色？
- 是否出现旧红色主品牌？
- Accent 是否只作为辅助？

# 11. 建议的截图验收

如果当前开发环境支持截图或浏览器自动化：

1. 使用接近 390px 的逻辑宽度；
2. 分别截取 6 张一级页面；
3. 保存在统一临时验收目录；
4. 与 Stitch `screen.png` 并排检查；
5. 对明显偏差继续修正。

如果当前环境无法自动截图：

- 至少启动可运行页面；
- 完成代码结构和样式检查；
- 在阶段汇报中明确说明“需要人工视觉截图验收”。

不要因为无法自动截图而声称视觉已完全对齐。

# 12. 当前已知错误示例

以下错误不得继续保留：

### 错误 1

```text
[光] 服务
社区生活服务，一站找到
```

把品牌图标、页面标题、副标题挤在一个导航区。

应恢复 Stitch 页面层级。

### 错误 2

```text
[缴]
物业缴费
```

使用汉字代替正式图标。

必须改为真实线性图标。

### 错误 3

每个 Quick Entry 外再套独立小边框卡片。

应改为 Stitch 的：

```text
图标底
+
标签
```

### 错误 4

Bottom Tab 每一项一个带边框的独立方块。

必须恢复轻量整体 Tabbar。

### 错误 5

为了复用 BaseCard，导致页面出现大量空白固定高度。

卡片高度必须随内容自然增长。
