# 2. 母版读取方式

开发某个页面时按以下顺序：

```text
PRD
→ 页面实施清单
→ MiniApp Design System
→ 微信小程序实现规范
→ 本映射表确定 Stitch Level + Visual Mode
→ 打开必要的 screen.png
→ 必要时读取 code.html
→ 使用 uni-app 公共组件实现
→ 按对应 Visual Mode 验收
```

`code.html`：

- 只看布局、模块顺序、视觉关系、尺寸关系；
- 不直接复制 Web DOM / Tailwind / 字体依赖；
- 没有 `code.html` 时不阻塞开发，以 `screen.png` 为主要视觉输入。

`screen.png`：

- L1 / L2 页面开发前必须直接查看必要母版；
- 若截图与 PRD 冲突，PRD 优先；
- R / O 两种模式的使用方式不同，见下一节。

## 2.1 Stitch Level 与 Visual Mode

页面开发必须同时确认：

```text
Stitch Level
+
Visual Mode
```

### Stitch Level

#### L1｜直接对应母版

当前开发页面存在一张直接对应的 Stitch 母版。

要求：

- 必须打开对应 `screen.png`；
- 可按需读取同目录 `code.html`；
- 不得跳过对应母版直接凭经验开发。

#### L2｜同类型参考母版

没有一一对应母版，但已有相同或相近页面类型。

要求：

- 选择 1 张主参考母版；
- 最多增加 1 张辅助参考母版；
- 业务字段必须来自当前 PRD；
- 禁止把参考母版中的业务内容照搬到当前页面。

#### L3｜无合适母版

没有可合理映射的 Stitch 页面。

要求：

- 按 Design System + 微信小程序规范生成；
- 优先复用已经成熟的公共组件和页面模式；
- 不自行创造第二套视觉体系。

### Visual Mode

#### R｜Replica Mode｜视觉还原型

适用于：

- Resident 主要页面；
- Merchant 入驻、认证、表单、状态说明、详情、核销等流程型页面；
- 已经确认 Stitch 构图合理的页面。

R 模式下，Stitch `screen.png` 是主要视觉验收基准。

优先保持：

- 模块顺序；
- 页面构图；
- 卡片组合关系；
- 图片比例；
- 信息层级；
- 主要留白比例；
- Bottom Action / Bottom Tab 的位置关系。

允许因微信运行环境产生合理差异：

- status bar；
- 微信胶囊；
- safe-area；
- 字体实际渲染；
- 设备高度；
- uni-app 实现方式。

#### O｜Operational Mode｜作业效率型

适用于 Merchant 高频作业和管理列表：

- 工作台；
- 商品/服务经营列表；
- 订单列表；
- 售后任务列表；
- 门店、人员、资质等需要连续管理多个业务对象的列表页。

O 模式下，Stitch 继续作为以下内容的参考：

- 色彩；
- Typography；
- 图标；
- 卡片质感；
- 状态语义；
- 品牌语言；
- 信息层级。

但 **Stitch 不作为像素级几何结构约束**。

允许为了移动作业效率调整：

- 卡片高度；
- 字段排列；
- 信息密度；
- 操作区域；
- 模块组合；
- 页面留白。

必须满足：

1. PRD 必要字段完整；
2. 高频状态容易识别；
3. 高频主操作直接可见；
4. 不制造无意义大卡片和大面积空白；
5. 一个列表卡原则上对应一个主要业务对象；
6. 紧凑视觉控件仍保证至少 44px 有效点击热区；
7. 不因紧凑损害可读性；
8. 不创造 PRD 未定义的新业务规则。

> **Merchant 页面不等于全部使用 O。**  
> 入驻、认证、编辑表单、状态说明、详情和高风险确认页面通常仍使用 R。

# 7. 禁止错误映射

- 不因为页面“看起来像”就复制其业务字段；
- 商户表单母版可用于居民表单，但商户经营上下文字段不能带过去；
- 居民售后与商户售后必须使用不同角色视角；
- Resident 页面不得出现 Merchant Tab；
- Merchant 页面不得出现 Resident Tab；
- 资金/支付文案不得从 Stitch Mock 复制渠道实现；
- “社区/秦淮地域感”不得演变成街道、网格员参与业务审批；
- 不得因为页面属于 Merchant 就全部套用 O 模式；
- 不得因为存在 L1 母版，就忽略 O 模式下的移动作业效率；
- 不得为了提高信息密度删除 PRD 必要字段；
- 不得为了达到 44px 触控规范，把所有视觉按钮强行绘制为 44–48px。

# 8. 母版冻结结论

当前 18 张 Stitch 页面已足以覆盖当前 01/02 以及 P2–P5 大部分常规移动页面类型。

后续只有出现下列情况，才建议新增 Stitch 母版：

1. 出现现有 18 张无法覆盖的全新交互类型；
2. 页面需要复杂地图/空间操作；
3. 页面需要全新的数据可视化模式；
4. 用户测试证明当前通用模式无法满足任务。

普通列表、详情、表单、缴费、订单、售后等页面直接从现有母版派生。

阶段开发完成后的最终 UI / UX 精修，不在本映射表中重新定义母版体系；统一在主要业务功能完成后，基于真实业务流、真实数据长度、真机和完整状态进行整体打磨。
