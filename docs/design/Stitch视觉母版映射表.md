# 2. 母版读取方式

开发某个页面时按以下顺序：

```text
PRD
→ 页面实施清单
→ Codex Design System V1.1
→ 本映射表确定 Stitch 母版
→ 打开对应 screen.png / code.html 参考构图
→ 使用 uni-app 公共组件实现
```

`code.html`：

- 只看布局、模块顺序、视觉关系；
- 不直接复制 Web DOM / Tailwind / 字体依赖。

`screen.png`：

- 作为视觉相似度参考；
- 若截图与 PRD 冲突，PRD 优先。

# 7. 禁止错误映射

- 不因为页面“看起来像”就复制其业务字段；
- 商户表单母版可用于居民表单，但商户经营上下文字段不能带过去；
- 居民售后与商户售后必须使用不同角色视角；
- Resident 页面不得出现 Merchant Tab；
- Merchant 页面不得出现 Resident Tab；
- 资金/支付文案不得从 Stitch Mock 复制渠道实现；
- “社区/秦淮地域感”不得演变成街道、网格员参与业务审批。

# 8. 母版冻结结论

当前 18 张 Stitch 页面已足以覆盖当前 01/02 以及 P2–P5 大部分常规移动页面类型。

后续只有出现下列情况，才建议新增 Stitch 母版：

1. 出现现有 18 张无法覆盖的全新交互类型；
2. 页面需要复杂地图/空间操作；
3. 页面需要全新的数据可视化模式；
4. 用户测试证明当前通用模式无法满足任务。

普通列表、详情、表单、缴费、订单、售后等页面直接从现有母版派生。
