# Stitch 视觉还原规范

> 适用终端：住户、商户两个独立 Vue 3 + uni-app 微信小程序
>
> 整理日期：2026-10-12（PREP-01/C-1）
>
> 本规范从历史视觉协议提取有效方法，不保留历史业务或阶段授权。

## 1. 职责与视觉权威

业务对象、字段、状态、权限和流程来自 [AGENTS.md](../../AGENTS.md) 所定位的有效产品和批准的阶段方案。本规范只规定视觉参考读取、还原方法和视觉证据。

视觉权威顺序：

1. [项目 Design System](MiniApp_Design_System_V1.1.md)。
2. [微信小程序实现规范](MiniApp_WeChat_Implementation_Guidelines_V1.0.md)。
3. 本 Stitch 视觉还原规范。
4. [映射表](Stitch视觉母版映射表.md) 中有效截图与两批原始 DESIGN 参考。

截图及 DESIGN 中的颜色、尺寸、布局只作为低优先级视觉参考；若与项目规范冲突，先记录差异。不得修改原始设计内容来迎合新业务，不把演示字段、时效、角色、审批、支付或 Mock 流程当成正式规则。

## 2. Level 与 Mode

每个已授权页面同时确定 Stitch Level 和 Visual Mode：

| Level | 含义 | 使用要求 |
|---|---|---|
| L1 | 存在有效的直接对应截图 | 开发前直接查看；按所选 Mode 对照 |
| L2 | 没有直接截图，存在相近类型 | 选择 1 张主参考，最多 1 张辅助参考；只借视觉模式 |
| L3 | 无合适有效截图 | 使用 Design System 和微信实现规范，复用成熟公共组件 |

| Mode | 适用视觉任务 | 对照重点 |
|---|---|---|
| R / Replica | 住户主要页面、合理构图的表单、说明、详情及确认页 | 模块顺序、构图、卡片关系、图片比例、信息层级和留白 |
| O / Operational | 商户高频工作台、对象列表与任务列表 | 品牌、字体、图标、状态视觉和任务效率；允许调整局部几何与密度 |

商户页面不是全部使用 O。流程表单、详情和高风险确认仍可使用 R。L1 也不自动要求 O 页面像素级复制卡片高度。

Mode 不能改变有效需求、字段完整性、状态和权限。R 模式允许为胶囊、安全区、大字体和设备尺寸作必要适配；O 模式紧凑控件仍需至少 44×44px 有效热区。

## 3. 页面任务前的读取

1. 确认当前页面已在批准范围内，并读取必要产品及阶段内容。
2. 读取本项目 Design System 和微信适配规范。
3. 查询映射表，记录 Level、Mode、主/辅助参考与截图状态。
4. 直接打开必要的有效截图；只读需要的原始 DESIGN 视觉段落。
5. 提取页面结构和视觉差异，再使用现有组件实现。

单页不加载无关母版或全部业务资料。历史 HTML 不作为正式开发输入或源码模板；因素材脚本依赖而暂存的历史输入也不具有规范效力。

## 4. 观察清单

| 要素 | 观察内容 |
|---|---|
| 页面背景 | 浅灰背景、白卡片、留白及轻边界，默认不整页纯白 |
| 顶部 | 品牌、标题、搜索、返回与胶囊安全区的层级 |
| 卡片 | 宽度、gutter、圆角、padding、间距、自然高度和嵌套 |
| 字体 | Page/Section/Card/Body/Meta/Price 的字号、字重与层级 |
| 图标 | 风格、重量、容器、文字关系和热区；不以 emoji 或汉字占位 |
| 图片 | 类型、比例、色调及失败占位；生活摄影不随意换扁平插画 |
| 底栏 | 正确端的 Tab 或 Bottom Action、主次关系及安全区 |
| 状态反馈 | 文案加视觉层级、加载/空/错/禁用及恢复路径；状态值来自接口 |

页面基底、卡片、字体、圆角、颜色和间距使用 Design System。不得为复用 BaseCard 固定不必要高度，也不得用重边框或大面积空白替代层级。

## 5. 几何、密度与组件

R 模式优先保留模块顺序、一行元素数量、图片和文本关系、卡片组合、主要留白及固定操作位置。必要平台差异逐项说明，不以“小程序不同”为理由重画整页。

O 模式优先突出首屏高频任务和主操作，减少重复状态、嵌套卡片与无意义说明区。允许调整字段排列、卡片高度及模块组合，但不能删除必要信息或降低可读性。

住户端维持生活感与较低信息密度；商户高频列表维持紧凑和清晰，流程任务维持正常移动表单密度。

优先复用 `packages/ui`、`packages/theme` 和已有页面模式。组件支持必要 Props/Slot 和视觉变体，不把某张截图的列数、卡片高度或业务字段硬编码为全局模式。

禁止复制 Web DOM、Tailwind、Google Fonts、Material Symbols Web Font、hover、桌面 media query、固定浏览器 viewport 或 Web-only JS。实现采用 Vue 3、uni-app 的 `view/text/image/scroll-view`、现有图标和安全区能力。

## 6. 视觉验证与证据

在当前任务允许的开发与验证范围内：

1. 运行目标页面并记录环境、逻辑视口、字体和设备条件。
2. 获取实际运行截图，按 Level/Mode 与有效参考对照。
3. 检查结构、几何、品牌、图片、图标、热区和反馈；修正授权范围内的明显偏差。
4. 回归受影响共享组件和另一端相关页面。
5. 分开记录自动化、构建、H5 视觉、mp-weixin 和真机结果。

项目响应基准为 390px 逻辑宽度，并补查窄屏和大字体。不能拿非匹配视口的截图作无说明的像素比较。O 模式还检查任务是否容易识别、主操作是否直接可见和滚动是否必要。

缺少运行截图时记录「待人工视觉验收」，不得宣称已完全还原。H5 不能代替微信开发者工具或真机的胶囊、安全区、键盘、扫码和资源验证；人工验收必须有本人确认。

证据保存位置遵循批准的阶段方案；无明确位置时使用临时目录，不将临时截图误认为原始 Stitch 资产。

## 7. 资产完整性与缺失处理

当前原 18 项截图中有 17 张完成图片完整性与解码核查。B2-_1 原文件为 28 字节错误文本，已清理；其直接截图缺失，不能标记为 L1 对照完成。

缺失或无法读取的截图按映射表记录候选 L2 回退，或按 L3 使用项目规范。回退组合在具体页面任务中确认，不复制其他角色的业务内容，也不伪造缺失截图。

原始两批 DESIGN 保持原内容，只作为视觉参考。图片可解码不表示素材内容、业务正确性或页面视觉验收已通过。

## 8. 双端保护与汇报

分别保护两端 App Shell、pages、TabBar、manifest/AppID、构建与发布。共享 Token 和组件不合并 Resident/Merchant 导航，也不产生第二套视觉系统。

每次视觉任务说明：页面和组件范围、Level/Mode、已读参考、平台适配差异、实际截图和检查结果、人工待办及缺失资产。未执行的检查标记 NOT_VERIFIED，阻断项说明来源；视觉工作不自动启动业务 Stage 或授权业务变更。
